# v0.6 方向：一个总管 + 平铺的员工

2026-11-15。这份文档记录和用户逐场景核对后确认的日常需求，以及据此对系统做的取舍。它优先于 `PLAN.md` 中与之冲突的部分。

## 确认的日常场景

| # | 场景 | 要的行为 |
| --- | --- | --- |
| 1 | 丢一句话就走 | 总管理解意图：小事直接干，大事或花费高的先给一份简短计划等批准 |
| 2 | 科研全流程 | 读论文 → 判断能否用于课题 → 设计实验 → 跑实验 → 分析，一个员工从头做到尾 |
| 3 | 长时间实验 | 本机或远程服务器，几分钟到过夜；跑完或出错时员工自己回来接着处理 |
| 4 | 只在四种情况被打断 | 结果与预期不符、要花大钱或长时间、要改动重要东西、反复失败卡住 |
| 5 | 交付 | 一页结论加证据，过程折叠 |
| 6 | 几件不相关的事同时进行 | 不同员工各干各的，互不干扰 |
| 7 | 各领域有自己的专家 | 每个员工有独立的记忆、规则、技能、MCP 工具和模型 |
| 8 | 主动盯守 | 邮件、新闻和新论文、实验状态，有情况才通知 |
| 9 | 越用越懂用户 | 记住课题、习惯、偏好 |
| 10 | 界面 | 输入框、待决定卡片、任务进展三样为主；简洁；外观可换；不需要流程图编辑 |

明确不要的：把一件事拆给多人并行。可以有的：交付前由另一名员工复核（可选）。

## 结构

- **总管**：用户唯一的对话对象（原"前台"+"主管"）。默认模型 Claude Opus 5.5。负责直接回答、选员工、判断开工方式（直接开工 / 先出计划）、转达补充。不干活、不验收。
  - 用户可以在 `~/.agentself/steward/user.md`（关于我）和 `~/.agentself/steward/rules.md`（给总管定的规则）里写自己的内容，总管每次都会读。
- **员工**：平铺，没有部门主管这一层。由用户自己命名和分类；"分类"只用于分组和帮总管选人。

## 三步走

1. **行为**（本次已做）：总管逻辑、员工技能、员工包去掉主管层。
2. **规则**（未做）：计划审批卡片的专用样式、花费和时长的硬阈值、长时间实验的看守、交付前复核、主动盯守模板（新论文 / 邮件 / 新闻）。
3. **界面**（未做）：首页只留三块、侧栏收成四项、去掉部门概念的残留页面。之后再决定是否继续以 Paperclip 界面为宿主。

## 第 1 步之后仍然存在的旧逻辑

- 团队层插件里的子任务等齐唤醒、返工计数、层数上限还在，只是员工技能不再让员工拆子任务，所以日常不会触发。第 2 步处理。
- 界面和数据里仍叫 `department`，含义已变成"分类"。旧数据里的主管仍是一个普通智能体，可以在员工页手动停用。
- "四种打断条件"和"先出计划"目前靠员工技能里的文字约束，没有代码保证。
