      一键模型策略
      
        
      
        
      
      
      
      
        
      
    
        

    
        
      
        前端不改内核一行代码，只扮演三个角色：事件源（派活）、通道（收汇报、答请示）、状态订阅者（驱动小人）。
        
      
        
        
        一个员工
        agents 里一个模型条目 + rules 里一条规则 + 一本技能手册
        
        
        下发任务
        POST /v1/events，type 为 task.<员工id>
        
        
        汇报
        回执里的 notice → 卡片 → office 通道 → 汇报栏
        
        
        请示
        回执里的 ask → 卡片；点按钮即 POST /v1/cards/:id/answer
        
        
        办公室动画
        订阅 GET /v1/stream，每条事实驱动一个小人状态
        
        
        主管拆活
        主管回执里的 events，hops +1，超过 8 层熔断
        
        
        模型/权限
        agents 条目的 command 与 access；同模型不同权限拆成两个条目
        
        
        皮肤
        纯前端的一份 JSON（UI 调色板 + 房间配色），内核完全不知道
        
      
        
      
        内核把事件正文当作数据，不拼进提示词。所以员工的指令来自规则里的 prompt 和技能手册，你写的任务内容作为本轮事件交给它读。
        
      
        按当前员工自动生成的 rules.json
